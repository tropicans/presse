  <behavior>
    - claimUploadJobs clamps requested batchSize to a maximum of 50 to prevent unbounded buffer memory allocation.
    - claimUploadJobs executes a raw SQL query selecting jobs with status PENDING and next_attempt_at <= NOW() AT TIME ZONE 'UTC' with FOR UPDATE SKIP LOCKED.
    - claimUploadJobs transitions claimed rows to status CLAIMED, increments attempts by 1, and updates updated_at timestamp.
    - markFileJobSynced transitions file_upload_jobs to status DONE, sets payload = NULL, and updates processed_at timestamp.
    - markFileJobSynced transitions submission_files to status SYNCED, storing bucket and objectKey.
    - markFileJobFailed with isTerminal=false updates file_upload_jobs with status PENDING, sets next_attempt_at, and records last_error.
    - markFileJobFailed with isTerminal=true updates file_upload_jobs with status FAILED and updates submission_files with status FAILED.
  </behavior>
  <action>
    Implement `claimUploadJobs(batchSize: number = 10)` in `src/lib/file-storage.ts` per D-02 and FILE-13. Clamp `batchSize = Math.max(1, Math.min(batchSize, 50))`. Inside a `prisma.$transaction`, select pending jobs whose `next_attempt_at <= NOW() AT TIME ZONE 'UTC'` using `FOR UPDATE SKIP LOCKED`, update their status to `'CLAIMED'`, increment `attempts = attempts + 1`, and update `updated_at = NOW() AT TIME ZONE 'UTC'`. Return an array of claimed jobs with their file metadata.
    Implement `markFileJobSynced({ jobId, fileId, bucket, objectKey }: { jobId: string, fileId: string, bucket: string, objectKey: string })` per D-02 and FILE-16. Inside a transaction, execute:
    UPDATE "file_upload_jobs" SET "status" = 'DONE', "payload" = NULL, "processed_at" = NOW() AT TIME ZONE 'UTC', "updated_at" = NOW() AT TIME ZONE 'UTC' WHERE "id" = $jobId;
    UPDATE "submission_files" SET "status" = 'SYNCED', "bucket" = $bucket, "object_key" = $objectKey, "updated_at" = NOW() AT TIME ZONE 'UTC' WHERE "id" = $fileId;

When `isTerminal` is false, set job `status = 'PENDING'`, `last_error = error`, `next_attempt_at = nextAttemptAt`. When `isTerminal` is true, set both job and submission file `status = 'FAILED'`, `last_error = error`.
    Write comprehensive unit tests in `src/lib/file-storage.test.ts` verifying SQL queries, parameter bindings, clamp behavior, and payload nulling assertions.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-48-05 | Tampering | Concurrent job claims | high | mitigate | `claimUploadJobs` uses `SELECT ... FOR UPDATE SKIP LOCKED` inside a transaction, preventing race conditions and ensuring no two worker threads claim the same upload job (per FILE-13). |
| T-48-06 | Denial of Service | Postgres bytea storage bloat | high | mitigate | `markFileJobSynced` and `cleanupOrphanedFiles` explicitly set `payload = NULL` in `file_upload_jobs` immediately upon job completion or orphan expiry, reclaiming disk space (per D-02, FILE-16). |
| T-48-07 | Denial of Service | Batch size memory spike | medium | mitigate | `claimUploadJobs` enforces `batchSize = Math.max(1, Math.min(batchSize, 50))` clamping to ensure worker never claims an unbounded number of in-memory bytea payloads in a single tick. |
| T-48-08 | Information Disclosure | Orphan GC retention window | low | mitigate | `cleanupOrphanedFiles` calculates time delta using explicit PostgreSQL UTC interval (`NOW() AT TIME ZONE 'UTC' - interval`), ensuring consistency regardless of server local timezone (per D-05). |
| T-48-SC | Tampering | npm packages | high | mitigate | Package-legitimacy gate: no new external packages added; all operations use existing PrismaPg adapter and native Node Buffer. |
</threat_model>
