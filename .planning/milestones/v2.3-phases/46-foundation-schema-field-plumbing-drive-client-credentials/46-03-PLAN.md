  <action>
    Create `scripts/ci-drive-smoke.mjs`. This is an ESM module (`.mjs`, top-level `await`), NOT a TypeScript file, and does NOT import from `src/lib/**` — the `src/lib` tree is Next/Turbopack-resolved and will not resolve under plain `node`. Use the SDK directly.

    Structure:
    1. Top of file: `import { GoogleAuth } from 'google-auth-library'` and `import { drive } from '@googleapis/drive'` (or the submodule equivalent your installed version exposes — inspect `node_modules/@googleapis/drive/index.js` if unsure).
    2. Read the three env vars with a small local helper that throws a clear message naming the missing var (do NOT reuse `src/lib/env.ts`). Mirror the `readRequiredEnv` behaviour but inside this script.
    3. Build the auth client with the SAME unescape as `getDriveConfig`: `privateKeyRaw.replace(/\\n/g, '\n')`. Scope is exactly `['https://www.googleapis.com/auth/drive.file']` — one element array.
    4. Upload a small fixture. Use an in-memory buffer containing a fixed sentinel string (e.g. `'form-drive-smoke-' + Date.now() + '\n'`), with filename `ci-smoke-${Date.now()}.txt` and `mimeType: 'text/plain'`. Call `driveClient.files.create({ requestBody: { name, mimeType, parents: [folderId] }, media: { mimeType: 'text/plain', body: Readable.from([buffer]) }, fields: 'id,name,driveId', supportsAllDrives: true })`. If the SDK version does not accept `Readable.from`, use `media.body: Readable` — Node's `node:stream` `Readable.from([Buffer])` is the correct shape for a Buffer.
    5. Get the folder's `driveId` by calling `driveClient.files.get({ fileId: folderId, fields: 'id,name,driveId', supportsAllDrives: true })`.
    6. Verify the uploaded file with `driveClient.files.get({ fileId: uploaded.id, fields: 'id,name,size,driveId,parents,trashed', supportsAllDrives: true })`.
    7. Assertions (each failing with a specific non-zero exit code):
       - folder has `driveId` — else abort with exit 2 and message `folder <id> bukan Shared Drive (tidak ada driveId)`;
       - uploaded file has `driveId === folder.driveId` — else abort with exit 3;
       - uploaded file's `parents` array includes `folderId` — else abort with exit 4;
       - uploaded file `trashed === false` (or `!== true`) — else abort with exit 5;
       - uploaded file `size` is a positive integer — else abort with exit 6.
    8. On success print a single line to stdout: `OK uploaded <fileId> name=<name> driveId=<driveId> parents=<folderId>`, then exit 0.
    9. Wrap the whole body in a top-level try/catch: on error print `ERR <exitCode?: 1> <safeReason>` where `safeReason` NEVER includes the private key, the client email, or `err.config.headers`. Reuse the same safe-message discipline as `describeSafe` in `src/lib/drive.ts` — a fixed enum-ish message like `timeout`, `HTTP 429`, `invalid_grant`. Do not `console.error(err)` on the raw error.

    The script must NOT clean up the uploaded file — a retained file is proof the upload really happened; the operator deletes it manually after seeing it in Drive UI.

    Do not add the script to `package.json` scripts. It is invoked with `node scripts/ci-drive-smoke.mjs` by the operator and (in this plan) only by the human-verify checkpoint in Task 3. Adding it to npm scripts invites accidental execution in CI without credentials, which would exit 1 for a non-issue.
